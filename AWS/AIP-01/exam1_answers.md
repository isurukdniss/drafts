### Question 1

A publishing company uses an Amazon Bedrock Managed Knowledge Base to augment a foundation model from unstructured editorial documents in Amazon S3. New and changed files arrive every hour, and they must be searchable during the same hourly cycle after normal propagation. The team cannot run release-window rebuilds. After releases, some recent documents are missing from answers, and operations sometimes lacks runtime metrics even though knowledge base requests succeed. The team needs automated controls for reliability and performance with low operational overhead.<br>Which steps should the team implement? (Select TWO.)

> **Answer:** A, D

#### A. Call StartIngestionJob after source changes. Poll GetIngestionJob to COMPLETE, record statistics, and retry query-readiness checks.

✅ **Correct**

> **Explanation:** Correct. Bedrock knowledge base synchronization is incremental and uses StartIngestionJob to process added, modified, and deleted documents. GetIngestionJob returns status and statistics, and newly synced embeddings can need a few minutes before they are queryable.

#### B. Create a replacement data source for each hourly batch. Sync the replacement, then remove the prior data source.

❌ Incorrect

> **Explanation:** Incorrect. This approach adds a recurring rebuild workflow when the scenario needs low-overhead hourly updates. Bedrock knowledge base sync is incremental, so replacing data sources is not the right control for routine file changes.

#### C. Allow cloudwatch:PutMetricData for the Bedrock runtime metrics namespace. Monitor model invocations as the knowledge base signal.

❌ Incorrect

> **Explanation:** Incorrect. Managed knowledge base runtime metrics use the AWS/Bedrock/KnowledgeBases namespace. Model runtime metrics do not replace direct monitoring of knowledge base invocations, errors, and throttles.

#### D. Allow cloudwatch:PutMetricData for AWS/Bedrock/KnowledgeBases. Monitor Invocations, ClientErrors, ServerErrors, and Throttles.

✅ **Correct**

> **Explanation:** Correct. Managed knowledge base metrics are published to the AWS/Bedrock/KnowledgeBases namespace. Metric publishing depends on PutMetricData permission, and Throttles must be monitored separately from ClientErrors and ServerErrors.

#### E. Use GetIngestionJob statistics as the readiness gate. Run freshness retrieval tests during the next release validation.

❌ Incorrect

> **Explanation:** Incorrect. The statistics object helps identify document-level ingestion success and failure, but it does not prove query readiness. Deferring freshness checks to release validation also misses the same-hour searchability requirement.

❌ Incorrect

> **Explanation:** Incorrect. Fixed-size chunking uses token limits and a percentage overlap between adjacent chunks. It does not provide a native rule for making each chunk match a proprietary article boundary.
